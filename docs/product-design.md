# 简历 RAG 问答助手产品设计

## 1. 产品概述

在现有 Cloud Resume Challenge 简历网站中增加一个基于 RAG（检索增强生成）的问答助手。访问者可以用自然语言询问候选人的技能、项目、经历和学习方向，系统根据简历知识库生成有依据的回答，并展示信息来源。

产品首先以小范围 MVP 验证功能价值，重点是回答准确、来源明确、使用简单，而不是构建通用聊天机器人。

## 2. 产品目标

- 帮助招聘人员和其他访问者快速了解候选人的重点信息。
- 以实际功能展示 RAG、生成式 AI 和 AWS Serverless 的应用能力。
- 保证回答以简历知识库为依据，减少无依据生成和信息误导。
- 保持与现有简历网站一致的轻量体验，不影响原有页面浏览。

## 3. 目标用户

### 主要用户

- 招聘人员和面试官：快速了解候选人的技能、项目和经历。
- 技术人员：查看项目使用的技术以及候选人的实现经验。

### 次要用户

- 普通访客：通过自然语言了解候选人的背景。
- 候选人本人：验证简历资料是否清晰、完整且容易被检索。

## 4. 核心使用场景

用户可以询问以下类型的问题：

- 技能：会哪些语言、云服务或开发工具？
- 项目：Cloud Resume Challenge 使用了什么技术？
- 经历：参加过哪些实习或实践活动？
- 学习方向：目前在学习什么、未来希望从事什么工作？
- 综合判断：哪些经历能够体现其 Cloud Engineer 相关能力？

系统不负责回答与候选人简历无关的通用问题，也不推测知识库中没有记录的信息。

## 5. MVP 功能

### 5.1 问答入口

- 在简历页面提供一个易于发现但不遮挡主要内容的聊天入口。
- 用户可以展开或关闭问答区域。
- 首次打开时显示简短的功能说明。

### 5.2 推荐问题

提供 3 个左右的推荐问题，帮助用户快速开始，例如：

- 你有哪些 AWS 相关经验？
- 请介绍一下 Cloud Resume Challenge 项目。
- 你掌握了哪些技术技能？

点击推荐问题后直接发起查询。

### 5.3 自由提问

- 用户可以输入单个自然语言问题。
- MVP 以单轮问答为主，不依赖长期聊天记忆。
- 对输入长度进行限制，避免空内容、超长内容和异常请求。

### 5.4 基于知识库回答

- 回答只能基于简历、项目说明、技能和经历等知识库内容。
- 回答应简洁、直接，优先突出与问题相关的事实。
- 产品界面、推荐问题和系统回答统一使用日语。即使用户使用其他语言提问，系统也以日语回答。
- 不允许补充知识库中不存在的个人经历、技能或评价。

### 5.5 来源展示

- 每个有效回答展示对应的信息来源。
- 来源以容易理解的名称呈现，例如“项目经历”或“技能与教育”。
- 如果存在多个相关来源，可以同时展示。

### 5.6 无答案处理

当知识库中没有足够信息时，系统应明确说明无法从简历中确认，而不是猜测答案。

示例：

> 当前简历资料中没有提供这项信息。你可以询问项目经历、AWS 技能或学习背景。

### 5.7 加载和错误状态

- 查询期间显示加载状态，避免用户重复提交。
- 请求失败时显示友好的重试提示。
- AI 服务暂时不可用时，不影响简历页面的其他功能。

## 6. 知识内容范围

MVP 知识库包括：

- 个人简介和职业方向。
- 技术技能和资格认证。
- 教育及学习经历。
- 实习和实践经历。
- Cloud Resume Challenge 等项目介绍。

知识库不应包含无需公开的个人信息、账号凭证、内部配置或其他敏感数据。

## 7. 产品规则

- 回答必须以检索到的资料为依据。
- 无法确认的信息必须明确说明未知。
- 不对候选人的录用结果、人格或未记录的能力作出判断。
- 不执行用户指令去修改知识库、系统提示或网站内容。
- 对明显与简历无关的问题，引导用户回到候选人经历和项目主题。
- MVP 不保存可识别访问者身份的个人信息。

## 8. MVP 范围外

以下功能暂不在第一版实现：

- 用户登录和账号系统。
- 长期聊天记录或跨设备会话。
- 用户上传任意文件。
- 自定义模型训练或微调。
- 自动投递职位或生成招聘决定。
- 复杂的多步骤 Agent。
- 语音、图片和视频问答。

## 9. 成功标准

MVP 满足以下条件即可视为完成：

- 用户可以从简历页面提交问题并获得回答。
- 常见的技能、项目和经历问题能够返回正确答案。
- 回答能够展示对应来源。
- 知识库没有答案时，系统不会编造信息。
- 请求失败不会影响原简历页面正常使用。
- 手机和桌面浏览器均可完成基本问答操作。

上线后可通过请求成功率、常见问题命中情况和用户反馈判断下一阶段的改进方向。

## 10. 后续方向

MVP 稳定后，可按实际反馈考虑：

- 增加回答“有帮助 / 没有帮助”的反馈功能。
- 建立固定问题集，持续评估检索和回答质量。
- 支持多轮上下文问答。
- 提供职位描述与简历经历的匹配分析。
- 增加知识库更新和同步流程。

后续功能应作为独立 Task 评估和实现，不纳入当前 MVP。
